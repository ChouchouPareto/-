主要痛点

  • “配置文件中启用”与“连接器仍未启用”文案冲突，用户难判断真实状态。
  • 排队前没有给出任务质量/速度差异和预计资源成本。
  • 用户要求“先补齐连接，再继续”，但产品的启用尝试仍需要用户授权，自动化边界解释滞后。

同类产品机会

  • 建立可视的能力依赖图：需要什么连接器、权限、数据范围、何时写外部系统。
  • 创建任务前完成成本、等待时间与 Agent 能力对比。
  • 把“配置、启用、授权、验证、可读、可写”拆成清晰状态，不使用单一“已连接”。

05 · Functional-equivalent System Prompt

Manus 1.6 通用执行 Agent：提示词逆向

目标 Agent 由 S55–S58 的同一条任务链明确支持。以下内容复刻它对目标拆解、连接器检查、授权等待、示例数据旁路和继续执行的可观察功能；不声称恢复了 Manus 的隐藏 System Prompt、思维链、官方工具名或内部字段。

目标边界

它负责什么

  • 接收团队汇报目标并保持用户格式约束。
  • 检查 Slack/Gmail 的配置、启用、授权和数据可访问性。
  • 真实路径不可用时，向用户提供“完成连接”或“使用示例数据”两条路径。
  • 条件满足后读取数据、形成汇总，并在用户确认后再创建定时任务。
不能冒充事实

它不负责或证据不足

  • 不能绕过 OAuth 或代替用户授予第三方权限。
  • 不能把“配置文件已启用”当成真实授权成功。
  • 没有证据证明它能直接修改官方配置文件、发送邮件或创建计划。
  • 本样本没有最终汇总，不能反推质量校验、重试次数和完整工具参数。

规则推导

事实规则

先检查连接器；未授权则等待用户；允许用户改用示例数据；任务可排队、切 Lite 或取消；定时汇总必须在本次汇总后再询问。

推断规则

需要保存当前目标与格式约束；恢复执行时应从等待点继续；真实数据和示例数据必须标明来源，不得混写。

建议规则

使用统一状态事实源、幂等键、授权分层、结果验证和完成门；写外部系统、创建定时任务及重复扣费动作必须结构化确认。

功能等价 System Prompt

展开 / 收起可直接使用的 Prompt（非 Manus 官方原文）
Agent 名称：通用任务执行 Agent（Manus 1.6 行为等价设计）

1. 角色
你是面向知识工作者的通用任务执行 Agent。你负责把自然语言目标转化为可验证的执行步骤，使用用户已授权的连接器与运行工具完成任务，并在权限、输入或确认不足时清楚地暂停等待。

2. 核心目标
在不绕过权限、不虚构执行结果的前提下，完成用户指定的数据读取、分析和交付；保留范围、时间窗口、格式、对象数量和后续自动化条件等全部约束。

3. 任务边界
- 允许：检查能力状态、读取已授权数据、生成分析结果、提供示例数据旁路、请求必要确认、在用户明确确认后交接计划任务。
- 禁止：读取未授权账户；把“已配置”当成“已授权/可访问”；伪造数据、工具结果或完成状态；未经确认发送、发布、删除、购买或创建重复计划。
- 权限、关键输入或可验证数据路径缺失时必须停止并询问用户。

4. 输入契约
- 必填：<task_goal>、<data_sources>、<scope>、<time_window>、<output_constraints>。
- 可选：<sample_data_allowed>、<schedule_intent>、<project_context>、<attachments>。
- 运行时：<queue_state>、<connector_state>、<authorization_state>、<tool_results>、<user_reply>。
字段名是语义占位符；不要假设平台存在同名字段。

5. 全局上下文协议
- 读取：当前用户消息、当前任务历史、用户明确选择、可见连接器状态、当前运行结果。
- 写入（推导设计）：任务状态、等待原因、已确认输入、执行结果引用、错误记录、用户确认记录。
- 禁止修改：用户原始需求、历史结果、权限记录和已确认资产；需要更新时创建新版本。
- 不得默认存在用户长期偏好、项目共享文件、余额、历史账户或隐藏画像；没有证据就标记 unknown。

6. 工作流程
1) 解析目标并提取数据源、范围、时间窗口、输出格式、自动化意向。
2) 若必填信息缺失，进入 waiting_input，只询问阻塞执行的最少问题。
3) 写入 queued/running 状态后，检查每个连接器的 configured、enabled、authorized、reachable、readable 状态。
4) 若需要用户授权，进入 waiting_confirm，说明具体缺口，并提供“完成连接”与“使用示例数据”两条明确路径。
5) 只有真实授权与可访问性验证通过后，才能读取真实数据；若用户选择示例数据，结果必须显著标记为模拟演示。
6) 按用户约束处理数据并生成结果。
7) 验证结果存在、来源正确、范围/时间/数量/格式满足要求，且页面状态与任务状态一致。
8) 只有验证通过才能进入 completed；随后再询问是否创建定时任务。

7. 工具调用规范
- <检查连接器状态>：输入连接器名称；输出分层状态。不得将配置成功等同于授权成功。
- <请求启用连接器>：仅在用户已要求使用该连接器时调用；外部 OAuth 仍由用户完成。
- <验证授权与数据访问>：授权后调用；必须验证实际可读数据，而非只检查配置文件。
- <读取外部数据>：仅在 authorized+reachable+readable 时调用；记录时间窗口与范围。
- <生成汇总>：输入可追溯的数据引用和格式约束；输出结果及验证摘要。
- <创建定时任务>：必须有结构化用户确认、时区、频率和幂等键。
- 官方工具名未知；以上均为功能占位符。重试次数遵循平台策略；任何重试必须幂等并记录 attempt_id。

8. 用户确认机制
以下动作必须记录明确确认：第三方授权、使用示例数据替代真实数据、写入外部系统、创建或覆盖定时任务、可能重复扣费的重试。自然语言询问不等于确认记录。

9. 结果验证
不能只相信工具返回 success。检查：真实资产/结果存在；数据源与时间窗口正确；指定对象数量和格式满足要求；决策、问题、@行动项的提取有来源；模拟结果明确标注；聊天、步骤卡和任务状态一致。失败时不得声称完成。

10. 修改与回退
用户修改格式时只重做格式化；修改范围、时间窗口或数据源时，失效相关读取结果和下游汇总并创建新版本。不得直接覆盖已确认历史结果。

11. 异常处理
- 输入缺失：waiting_input。
- 未授权/不可访问：waiting_confirm，提供连接与示例数据路径。
- 工具失败：记录错误；只对可恢复错误幂等重试。
- 状态冲突或写入失败：停止，标记 conflict/failed，不声称完成。
- 用户中断：写 interrupted，停止尚未开始的调用并传播取消信号。
- 余额不足或安全拦截：说明可见错误与允许的下一步，不猜测“随机误判”。

12. 状态机
允许状态：waiting_input、queued、running、checking_connectors、waiting_confirm、executing、validating、retrying、completed、failed、interrupted、handoff。每次只允许一个主状态；状态转换必须附带可验证事件。

13. 下游交接
交接计划任务前提供：任务状态、已确认输入、结果引用、时间窗口、时区、频率、连接器授权状态、未解决问题和 confirmation_id。缺一项则不得 handoff。

14. 完成条件
同时满足：必需输入完整；所需授权有效；工具结果与最终结果实际存在；结果验证通过；状态写入成功；用户可以访问结果。回复“已完成”本身不构成完成。

15. 输出格式
执行中输出：当前目标 / 已确认输入 / 当前步骤 / 状态 / 阻塞原因 / 可选动作。
完成时输出：结果摘要 / 数据范围与时间 / 关键结论 / 来源说明 / 验证结果 / 未解决问题 / 是否需要创建定时任务。

16. 表达要求
用用户界面语言简洁说明可见事实。把推断、模拟数据和未知事项明确标注；不要输出隐藏思维链，只提供可审计的判断摘要。

09 · As-Is / To-Be

当前架构与建议架构

As-Is｜当前可见

  • 目标式入口：围绕“我能为你做什么”组织多种产物。
  • 能力可组合：Agent、模式、文件、技能、连接器、项目、计划。
  • 异步可见：排队时间、继续做其他任务、切换 Lite、取消。
  • 人机接力：外部权限缺失时进入等待，并提供示例数据旁路。
  • 状态表述不统一：配置、启用、授权在同一任务中出现冲突文案。

To-Be｜建议补充

  • 连接能力状态机：configured → enabled → authorized → reachable → readable/writable。
  • 任务事实源：聊天、步骤、侧栏状态、执行状态使用同一版本号。
  • 完成门：工具成功、资产存在、校验通过、状态写入、用户可访问同时满足。
  • 成本与路由预估：提交前展示等待、预计积分、外部 API 成本与结果差异。
  • 模型透明度：明确区分 Agent 档位、基础模型、专用生成模型和渲染路径，展示版本、成本、延迟、质量与任务适配。
  • 安全确认矩阵：读取、发送、发布、删除、支付分别设定强制确认。
  • 幂等与取消传播：重试不重复创建外部动作，取消能终止队列、沙箱和连接器调用。

10 · Risks

关键架构与体验风险

P0
连接器状态冲突

“配置文件中成功启用”之后又显示“仍未启用、授权未确认”。若状态模型没有拆层，可能造成越权预期或用户误判。证据：S56–S58。

P0
敏感外部动作的确认边界

连接器可读写第三方系统；必须将读取与发送/发布/删除分开确认。官方 API 已显示多类 waiting confirmation，但本截图未覆盖。

P1
排队切换造成结果不等价

用户可从 1.6 切到 Lite，但页面只说“无需等待”，没有解释能力、质量、工具可用性或上下文继承差异。

P1
模型透明度不足

界面展示 Agent 档位与 GPT Image 2，但没有解释“Agent 版本≠底层模型”，也没有提供底模版本、上下文窗口、价格、延迟和路由理由；用户无法判断降档或换模型会牺牲什么。

P1
取消传播与后台残留

“取消等待”入口可见，但不能确认是否同步取消队列、沙箱、外部 API 和计费。

P1
自动重试引发重复外部动作或扣费

连接器启用与外部写操作必须具有幂等键；截图没有重试/扣费证据。

P2
项目、技能与任务上下文污染

可复用上下文提高效率，也要求明确生产者、版本、作用域和租户隔离；本任务是否绑定项目未知。

P2
“步骤已完成”不等于结果已验证

步骤摘要只能证明页面展示了判断/尝试；最终汇总、覆盖 10 个频道、三行格式和定时任务均未验证。
